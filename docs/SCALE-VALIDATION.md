# ORDERFLOW 동시 주문 안정화 및 검증 기록

검증일: 2026-09-02 (Asia/Seoul)

## 변경한 처리 경계

- 주문 입력 정규화와 가격·재고 계산을 순수 도메인 모듈로 분리했습니다.
- 상품별 개별 `INSERT`/`UPDATE`를 14개 단위 주문항목 삽입과 1회 재고 갱신으로 묶었습니다.
- 재고 차감은 기존 음수 재고 방지 트리거와 D1 배치 트랜잭션 안에서 수행합니다.
- 동일 `idempotencyKey`는 정규화된 요청 해시가 같을 때만 기존 주문을 반환합니다. 내용이 다르면 409로 거절합니다.
- D1의 일시적인 연결 재설정·과부하 오류는 지수 백오프와 지터로 최대 3회 재시도합니다.
- 주문 요청 중 실행하던 오래된 제한 기록 삭제는 매일 예약 작업으로 옮겼습니다.
- 고객별·주문서별 제한 지문을 사용해 동일 네트워크의 여러 고객이 한도를 공유하지 않게 했습니다.
- 사업자 주문 목록은 `(created_at, id)` 복합 커서로 60건씩 불러오며 15초마다 새 주문을 확인합니다.

## Cloudflare 격리 스테이징 결과

운영 DB와 분리된 `orderflow-upgrade-staging-db` 및 전용 Worker에서 실행했습니다.

| 시험 | 결과 | 지연 |
|---|---:|---:|
| 200명, 각 20개 상품 동시 주문 | 201 성공 200/200 | p95 3.03초 |
| 500명, 각 20개 상품 동시 주문 | 201 성공 500/500 | p95 5.31초 |
| 재고 100개 상품에 200명 동시 주문 | 201 100건, 409 100건 | DB 주문 100건, 재고 0 |
| 같은 주문 100회 동시 제출 | 201 1건, 재사용 99건 | DB 주문 1건 |

500명 시험 처리량은 초당 87.66건이었고 연결 실패와 HTTP 500은 없었습니다.

## 운영 판단 범위

이 결과는 수백 명이 한꺼번에 주문하는 현재 목표를 검증한 것입니다. 무제한 용량 보증은 아닙니다. 수만 명이 같은 몇 초 안에 결제·재고 확정까지 요청하는 단계에서는 사업자별 데이터 분리, Durable Objects 기반 재고 직렬화, Queues 기반 후속 처리, 결제 공급자 멱등성, 대기열 화면을 다음 확장 경계로 둡니다.

스테이징에는 합성 시험 상품과 합성 주문만 사용하며 운영 고객 데이터는 복제하지 않습니다.
