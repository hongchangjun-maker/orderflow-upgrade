# 로그인 없는 임시 테스트 진입

## 변경 및 보존

- 기본 주소 `/` → `/try` → 별도 Cloudflare 스테이징의 자동 테스트 접속입니다. 기존 간이 데모가 아닌 현재 원본형 주황색 관리 화면과 실제 내부 API를 사용합니다.
- 로그인·비밀번호 입력 없이 브라우저별 독립 테스트 매장을 생성합니다. 청과20품목과 예시 주문3건이 준비됩니다. 새로고침은 같은 세션을 재사용합니다.
- 샘플·추가 주문은 별도 staging D1에 실제 저장합니다. 운영 D1/R2·원본 앱·원본 데이터와 연결하지 않습니다. 운영 `/replica`, `/workspace`와 API는 인증을 유지합니다. 기존 `/sign-in`도 임시로 테스트 진입으로 연결하며 정식 관리자 로그인은 `/sign-in?mode=live`로 보존합니다.
- 자동 세션은 무작위 토큰의 해시만 DB에 보관하고 HttpOnly/Secure/SameSite=Lax 쿠키를 사용합니다. 비밀번호 로그인이 가능한 계정을 공개하지 않습니다. 브라우저별 상점 권한은 분리되며 기존 서버 로그아웃으로 세션이 폐기됩니다.
- 세션12시간, 초기 샘플 주문서도12시간 접수 후 마감합니다. 데이터 자동 삭제를 의미하지 않습니다. 실제 개인정보·배송 주소를 입력하지 마세요. 신규 매장 생성은 IP별 시간당20회로 제한합니다. 외부 공급자 연동은 계속 비활성입니다.

## 종료 및 복구

운영 `wrangler.jsonc`의 PUBLIC_TEST_ENTRY를0, staging의 PUBLIC_TEST_MODE를0으로 설정하고 각 Worker를 재배포하면 기본 운영 진입을 복구하고 기존 테스트 세션도 차단합니다. 기존 데이터·계정·비밀값을 삭제하거나 변경할 필요는 없습니다. 코드 롤백 기준은 이전 운영 버전 `eac214db-844b-4190-a3fe-45d76682bf37`입니다. 추가 DB 마이그레이션은 없습니다.

## 검증

- 기존51개 및 추가4개 단위 회귀: 환경 게이트, guest 매장 범위, 테스트 모드 종료 시 기존 세션 차단, 일반 직원 인증 보존.
- 실제 빌드 렌더링·보안8개: 운영 환경은 PUBLIC_TEST_MODE=1이 잘못 설정돼도 테스트 세션 발급을 거절하며 기본 로그인 숨김/명시적 운영 로그인 보존도 검증합니다.
- `node tests/test-entry-http.mjs`: 별도 staging에서 출처 차단, 자동 접속, 세션 재사용,20품목/3주문, 두 브라우저 상점 격리, 고객 주문 저장/중복 방지/격리, 로그아웃 폐기7개 시나리오.
- 실제 브라우저: `/try`에서 아무 자격증명 입력 없이 `/replica/orders`로 전환되고 테스트 고객3명·주문3건과 테스트 모드 표시를 확인했습니다. `outputs/login-free-test.jpg`.
- 배포 후 운영 점검은 읽기와 의도적으로 거절되는 요청만 사용합니다. 최종 버전·CI는 릴리스 기록에 추가합니다.

공개 테스트 staging에는 실제 문자·결제·은행 공급자 키를 설정하지 않습니다. 외부 연동은 테스트 공개를 종료한 뒤 별도 운영 설정과 승인을 거쳐야 합니다.
